设计说明 — 改了什么、为什么、怎么落地

1. 新增常驻命令行（核心诉求：配置 LLM 不用再翻代码）
  • 底部固定一行 ❯ 输入行，任何页面按 : 或 / 即呼出，输入即弹出补全（命令名 + 描述 + 用法示例），不用先切到控制台页。
  • 配置 LLM 有两条路：快路——一行命令 llm model gpt-4o / llm key sk-... / llm test，即时生效；慢路——:config llm 打开设置页表单（服务商/模型/Base URL/Key/温度），适合首次配置和不确定参数时。
  • 控制台页回归本行：只放输出历史。输入与输出分离，回看时不会被输入框挤占。
  • 顶栏在「状态·目标·计时」铁律之外增加一个 LLM 状态位（当前模型），配置错误第一时间可见。
2. 布局配方变化（对应 layout.rs 的 root()，只加一行） 
现状：  头1 · 横幅2 · 页签1 · 主体(弹) · 脚1
新增：  头1 · 横幅2 · 页签1 · 主体(弹) · 命令行1 · 脚1
root() 的 Constraint 数组插入一条 Length(1)，主体 Min(0) 自动让位——正如注释里预留的「审批条」扩展点，改布局仍然只碰 layout.rs 一个文件。
3. 设置页为什么是「第 5 个页签」而不是模态框 你的架构里 Page 枚举 + renderer 注册表就是现成的页面扩展点（加变体 + 加一行注册，编译器逼你补全）。模态框需要另造一套 overlay 状态机和焦点管理，与现有机制重复。所以：设置 = Page::Settings，:config 命令只是导航过去；后续若想要「快速编辑」体验，把 llm model 这类一行命令做成即时生效即可（原型里已演示）。
4. 交互规则（输入优先，防止误触）
按键行为
: / /呼出命令行（首字符自动填入）
Tab补全浮层中=补全到选中项；否则=翻页
↑ ↓在补全项间移动（循环）
Enter执行；结果进控制台历史
Esc关浮层 → 再按退出命令行
q仅在不输入时退出；命令行激活时 q 是普通字符
5. 落地到代码的映射（供你自行写入，保持指导式协作）
  • layout.rs：root() 加 Length(1) 命令行行，RootAreas 加 cmdbar 字段。
  • types.rs：Page 加 Settings（ALL/CHAIN 同步）；App 加 CommandLine 状态（buffer、补全索引、history）。
  • chrome.rs：新增 cmdbar() / completion_popup() 零件，样式进 palette.rs（prompt=accent、选中=selected 复用现有配色）。
  • controller.rs：键位路由——表单焦点态（设置页）与命令行态两套，Esc 是唯一「后退」键。
  • 命令注册表放 orchestration/command（已有空模块），视图只消费——命令清单仍是唯一真相来源。
6. 本原型范围 纯 HTML/CSS/JS 单文件，无外部依赖；演示数据（扫描 62%、五级发现各 1 条）与现界面一致；所有命令执行为模拟输出，不会真正发包或写配置。可直接把此文件当验收基线：TUI 实现后逐屏对照。
